# Spec+RFC 到 OpenSpec 检查清单

## 高风险语义

- 必须、不得、禁止、仅、全部、至少、最多。
- 前置、发布前、人工处置、阻止、中断、失败、报错。
- 兼容、保持不变、回滚、恢复、备份和迁移。
- 唯一、空值、索引、约束、主键、事务、幂等和并发。
- 权限、密钥、敏感数据、信任边界、审计和安全降级。
- TBD、假设、来源、推导和用户确认。

## 常见漏项

1. 前置检查只在 proposal 出现，没有进入 tasks。
2. 兼容要求没有对应回归 Scenario。
3. “失败或阻止”被弱化为 warning。
4. “仅某范围”被扩大到全部场景。
5. 测试、回滚和运维要求没有可执行任务。
6. MODIFIED requirement 只写增量，归档后丢失原语义。
7. 设计推导没有标注来源或确认状态。

每个发现必须包含源位置、OpenSpec 位置、差异类型、影响和最小修正建议。
