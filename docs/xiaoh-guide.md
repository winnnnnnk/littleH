# XiaoH 使用指南

## 提需求

直接告诉 XiaoH 目标、现象或想法即可。XiaoH 会先核对当前事实，再整理推荐方案、影响和真正需要你决定的业务结果。确认一次基线后，授权范围内的分析、实现、验证、文档和收口会自动继续。

## 业务项目

XiaoH 会先识别当前 Workspace 的项目和系统归属，召回相关历史并与当前代码、配置和任务状态对账。复杂需求会形成 Spec+RFC；你确认后再派生 OpenSpec 和实现任务。需要额外把关时，可以按需调用两个需求工件检查 Skill；它们只输出当前修订的一次性结论，不会自动形成复查轮次。

## 实现

XiaoH 根据任务选择 Java 探索、架构、实现、前端或 PKI 专家。实现者只写入明确的单仓范围。完成后运行与风险匹配的测试、构建、静态、契约和安全检查；失败会回到根因修复。

## 知识

稳定成果会立即写入任务记录，业务项目同时刷新项目进度。每日任务只推送已经收口的成果。知识候选只有在你确认后才晋升为项目知识、领域知识、复用方法或个人系统规则。

## 安装与维护

- 首次或干净重装：`$xiaoh:xiaoh-setup`
- 同版本同步/修复：`$xiaoh:xiaoh-update`
- 安装诊断：`$xiaoh:xiaoh-doctor`

安装会创建恢复备份。Hook 发生变化后重启 Codex，并在 `/hooks` 中信任四个 XiaoH Hook。XiaoH 不会替你安装或改变 Playbook CLI 版本。
