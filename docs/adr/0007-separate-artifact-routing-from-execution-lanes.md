# ADR-0007：将需求工件路由与执行通道分离

- 状态：已接受
- 日期：2026-08-01
- 来源：`docs/spec-rfc/xiaoh-4.0.0-runtime-rewrite.md` 修订 3

## 背景

XiaoH 已移除自动代码评审循环，但编码任务仍缺少按风险分流的明确契约。若所有改动都使用完整需求与全量验证，小型局部修复会承担无关成本；若完全依赖模型临时判断，又难以发现误降级。

## 决策

保留 `artifact_route` 负责需求事实源，新增 `execution_lane` 负责实现与验证深度。执行通道分为 `fast`、`standard` 和 `high_risk`。

低风险、局部、可逆、验收明确且不产生新持久语义的改动可使用 `direct_change` 和影响面验证。高风险工作必须使用 `high_risk` 和完整适用门禁。Agent 只有在用户授权且存在明确实质收益时才能使用。

Validator 拒绝风险与通道不一致、直接改动携带风险信号、无授权或无收益委派，以及缺少验证证据摘要的完成记录。

## 备选方案

- 所有任务统一使用完整需求与全量验证：规则简单，但低风险任务成本过高。
- 只在 Skill 中给出建议，不扩展任务上下文：改动最少，但误降级和委派膨胀不可机械发现。
- 新建独立工作流引擎：表达能力强，但会形成第二套状态机和不必要复杂度。

## 后果

- 局部修复可以减少工件、上下文和无关测试成本。
- 高风险任务仍保持需求、安全、恢复和完整验证门禁。
- schema 1.6 任务上下文增加执行通道字段；schema 1.2 完成记录需要一次验证证据摘要。
- 发现新业务、接口或风险语义时必须升级路线，不能继续沿用 `direct_change`。
