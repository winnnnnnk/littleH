# ADR-0005：代码评审保持显式和单次

- 状态：已接受
- 日期：2026-08-01
- 来源：`docs/spec-rfc/xiaoh-4.0.0-runtime-rewrite.md`

## 背景

旧代码评审 Campaign 将评审、修复和再次评审串成长期循环，耗时高且不能替代确定性验证。另一方面，针对固定 Diff 的规范和需求符合度检查仍有独立价值。

## 决策

XiaoH 4.0.0 提供显式单次代码评审。只有用户明确请求时才运行，必须固定比较点，并将规范轴和需求轴分开报告。

评审不自动修复、不自动重评、不创建 Campaign，也不作为开发完成后的默认门禁。构建、测试、静态检查和契约验证继续承担确定性验收。

## 备选方案

- 完全不提供代码评审：流程最简单，但失去固定 Diff 的人工判断能力。
- 恢复自动评审门禁：覆盖面看似更大，但重新引入循环和时间成本。

## 后果

- 用户可以按需获得代码评审，而不会拖慢默认开发流程。
- Skill 触发条件和结束条件必须通过契约测试固定。
- 如使用 Agent，仍需满足 XiaoH 正式委派门禁。
