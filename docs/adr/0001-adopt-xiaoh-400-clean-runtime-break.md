# ADR-0001：采用 XiaoH 4.0.0 干净运行时断代

- 状态：已接受
- 日期：2026-08-01
- 来源：`docs/spec-rfc/xiaoh-4.0.0-runtime-rewrite.md`

## 背景

XiaoH 3.1.2 的产品能力需要保留，但其内部模块依赖、安装生命周期、诊断编排和 Schema 已不适合作为下一轮演进基础。继续兼容旧运行时会迫使新实现维护双入口、双状态和历史恢复分支。

## 决策

XiaoH 4.0.0 全面重写内部运行时。新版本保留 3.1.2 的产品能力和用户长期资产导入语义，但不兼容 2.x 或 3.1.2 的内部运行时、安装状态、事务证据和内部 Schema。

本阶段只生成仓库内可安装候选，不安装本机。未来本机安装需要用户单独授权。

## 备选方案

- 继续在 3.1.2 上局部修补：改动较小，但保留现有依赖和生命周期债务。
- 同时维护新旧运行时兼容：迁移表面平滑，但长期复杂度和恢复风险过高。

## 后果

- 新实现可以重新建立清晰的模块、事务和诊断模型。
- 未来安装必须采用干净部署和用户长期资产导入。
- Git 历史负责代码回退，生产代码不保留废弃实现。
