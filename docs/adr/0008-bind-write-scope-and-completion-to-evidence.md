# ADR-0008：将写入范围和完成结论绑定到可复算证据

- 状态：已接受
- 日期：2026-08-01
- 来源：`docs/spec-rfc/xiaoh-4.0.0-runtime-rewrite.md` 修订 4

## 背景

原有 schema 1.6 能表达任务范围和验证命令，但部分字段只检查外壳；schema 1.2 也允许用状态字符串描述“已通过”。这能帮助模型组织工作，却不足以阻止越界写入、来源漂移或没有执行证据的完成声明。

## 决策

保留 schema 1.6 和 schema 1.2 的公共版本，强化其必填结构和证据语义。必需来源携带路径类型与 SHA-256；验证项携带稳定 ID、类别、命令和必需标记；通过结果携带退出码、起止时间、证据路径和摘要。

根任务写入前建立短时执行绑定，记录当前上下文摘要、允许路径、受管 Git 仓库和既有改动。必需验证由绑定控制的入口执行，证据自动记录上下文、绑定、验证 ID、原命令、退出码和时间，只保存 stdout/stderr 的 SHA-256，不保存原始输出。Hook 对补丁和可确定的命令目标做前置检查，任务结束时再从绑定前后的 Git 状态、文件摘要和提交差异生成范围证明。最终证明是权威边界，不能由 shell 文本解析或模型自述替代。

委派策略增加 `allowed_paths` 和 `read_only`。写 Agent 的范围必须包含于根任务范围，并且彼此不重叠。

## 备选方案

- 只加强提示词：实现成本最低，但无法拒绝伪造状态或真实越界改动。
- 完整解析任意 shell：看似严格，实际上无法可靠覆盖脚本、管道、子进程和工具内部写入，复杂度和误报都过高。
- 强制每次改动执行代码评审：不能证明权限和执行事实，还会恢复已经移除的评审循环。

## 后果

- 实现任务多一次绑定和一次范围证明，但不增加评审轮次。
- 来源或上下文漂移会在副作用前失败，验证日志缺失或摘要不符会在收口失败。
- Hook 能提前拦截明确越界目标；未被命令解析识别的写入仍会被最终 Git 证明发现。
- 语义质量、业务取舍和推荐方案继续由 XiaoH 判断，不被机械门禁替代。
