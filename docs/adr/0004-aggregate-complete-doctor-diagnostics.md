# ADR-0004：Doctor 聚合完整诊断

- 状态：已接受
- 日期：2026-08-01
- 来源：`docs/spec-rfc/xiaoh-4.0.0-runtime-rewrite.md`

## 背景

当前 Doctor 在已有静态错误时会跳过部分动态检查，命令检查遇到首个失败后停止。这会让问题在多次执行中逐个出现，增加修复和沟通成本。

## 决策

Doctor 只负责编排独立诊断器。一个诊断失败不阻止其他独立且安全的诊断执行。依赖不足或继续执行不安全时，关联诊断返回 `skipped` 和原因。

Doctor 一次聚合 facts、errors、warnings、remediation 和运行时检查状态，但不执行修复。

## 备选方案

- 保留首错退出：实现简单，但继续产生逐轮发现问题。
- Doctor 自动修复后再次运行：自动化程度高，但会恢复旧的循环和副作用不透明问题。

## 后果

- 用户一次获得更完整的问题集。
- 诊断器必须拥有明确依赖和副作用边界。
- 输出量可能增加，但可以通过结构化分组保持可读性。
